КОНТРОЛЬ СРОКОВ: ДОМЕНЫ, SSL-СЕРТИФИКАТЫ И РЕГУЛЯРНЫЕ ПЛАТЕЖИ (эпизод 36)
=====================================================================

ЧТО ВНУТРИ АРХИВА
- billing_monitor_n8n.json  готовый сценарий n8n (импортируется одной кнопкой)
- assets_template.csv       таблица учёта: домены, сертификаты, платежи (все строки это примеры)
- Инструкция.txt            этот файл

КАК ЭТО РАБОТАЕТ
Раз в сутки (09:00) сценарий читает таблицу assets.csv и для каждой строки узнаёт срок окончания:
- kind=domain: запрос к публичному реестру RDAP (современная замена WHOIS), адрес rdap.org;
- kind=ssl: прямое TLS-рукопожатие с сервером (читается дата окончания сертификата);
- kind=manual: дата берётся из колонки due_date (хостинги, лицензии, подписки, домены .ru и .рф).
Затем считаются календарные дни до окончания, и в Telegram уходят сообщения:
- за 14 дней: напоминание;
- за 3 дня: предупреждение;
- за 24 часа и дальше (в день окончания и после просрочки): тревога каждый день, копия второму ответственному, если вы указали его chat_id.
Сторонние платные мониторы не нужны: достаточно своего n8n и своего Telegram-бота (без абонентской платы).

ЧТО НУЖНО ЗАРАНЕЕ
1. Свой n8n (на сервере или компьютере, где он работает постоянно). Сценарий собран для актуальных версий n8n, но на живом экземпляре автором НЕ запускался: после импорта прогоните вручную.
2. Telegram-бот: напишите @BotFather, команда /newbot, сохраните токен. Токен храните только в учётных данных n8n, в файл сценария его вписывать нельзя.
3. Ваш chat_id: напишите боту любое сообщение, затем откройте в браузере https://api.telegram.org/bot<ТОКЕН>/getUpdates и найдите "chat":{"id": ...}. Для группы бот должен быть добавлен в неё.

ШАГ ЗА ШАГОМ
1. Скопируйте assets_template.csv в папку файлов n8n под именем assets.csv. Для Docker это папка /home/node/.n8n-files (подключите её томом). Замените примеры своими строками.
   Колонки: id, name, kind, provider, due_date, amount_rub, port, owner, note. Первую колонку id не переименовывайте (так безопаснее при сохранении из Excel в «CSV UTF-8»).
2. Для проверки SSL добавьте переменную окружения n8n: NODE_FUNCTION_ALLOW_BUILTIN=tls и перезапустите n8n. Без неё узел «SSL: срок сертификата» вернёт ошибку.
3. В n8n: Workflows -> Import from file -> billing_monitor_n8n.json.
4. Откройте узел «Telegram: алерт», создайте учётные данные Telegram API (токен бота).
5. Откройте узел «Остаток дней и уровень» и впишите CHAT_MAIN (ваш chat_id в кавычках). CHAT_ESCALATION (второй ответственный) можно оставить пустым.
6. Нажмите Execute Workflow. В тестовых строках есть примеры: чтобы сразу увидеть сообщение, поставьте в одной manual-строке дату на 3 дня вперёд.
7. Включите сценарий переключателем Active.

ЧЕСТНЫЕ ОГРАНИЧЕНИЯ (проверяйте актуальные условия сервисов)
- Публичные серверы WHOIS и RDAP ограничивают частоту запросов. Поэтому проверка идёт раз в сутки; не ставьте интервал в минуты и не загружайте сотни доменов за один запуск.
- Зоны .ru и .рф: на момент записи (2026-11-08) запрос к rdap.org для yandex.ru вернул 404, то есть сервис эти зоны не отдаёт. Для них используйте kind=manual и дату из кабинета регистратора. Прямой адрес RDAP российского реестра с машины автора не открылся, поэтому не проверен.
- Проверка SSL работает только для хостов, до которых доходит сервер n8n, и только по порту из колонки port (по умолчанию 443).
- Сценарий НЕ платит за вас и не продлевает ничего: он только предупреждает. Автоплатёж у регистратора и хостинга всё равно проверяйте после перевыпуска корпоративной карты.
- Уведомления об истёкшем сроке приходят каждый день, пока срок не обновится (для domain и ssl это происходит само, для manual измените due_date).
- Кириллические имена доменов вносите в виде punycode (xn--...).
- Таблица assets.csv единственный источник данных. Сделайте её копию на другом носителе (правило 3-2-1) и храните вне папки с сервером.
- Все суммы, имена и домены в шаблоне примеры.
