# Контроль сроков доменов, SSL и платежей: воркфлоу n8n и Telegram

Набор к ролику «Автоматический контроль оплаты регулярных счетов и подписок: домены, SSL, хостинги». Автономный воркфлоу n8n раз в сутки читает таблицу активов, узнаёт сроки окончания и присылает алерты в Telegram за 14 дней, за 3 дня и за 24 часа, дальше каждый день с копией второму ответственному. Без абонентской платы за сторонние мониторы: нужны свой n8n и свой Telegram-бот.

Канал с материалами: [@ByteAutomate_AI](https://t.me/ByteAutomate_AI). Единый диспетчерский центр цифровых активов под ключ: @konstantin_100.

```bash
git clone https://github.com/Kavilucky/ep36-billing-monitor && cd ep36-billing-monitor
```

## Что внутри
| Файл | Для чего |
|---|---|
| `billing_monitor_n8n.json` | сценарий n8n (13 узлов), импортируется кнопкой Import from file |
| `assets_template.csv` | таблица учёта: домены, сертификаты, платежи (все строки это примеры) |
| `Инструкция.txt` | пошаговая инструкция для новичка и честные ограничения |

## Как это работает
1. **Расписание** запускает сценарий каждое утро в 09:00.
2. Читается `assets.csv`, колонка `kind` направляет строку в одну из трёх проверок:
   - `domain`: запрос к RDAP (`https://rdap.org/domain/<домен>`), берётся событие `expiration`;
   - `ssl`: TLS-рукопожатие с хостом, берётся дата окончания сертификата;
   - `manual`: дата из колонки `due_date` (хостинги, лицензии, подписки, домены `.ru` и `.рф`).
3. Узел Code считает календарные дни до окончания.
4. Фильтр пропускает пороги 14, 3, 1 и 0 дней, просрочку и ошибки проверки.
5. Telegram-узел шлёт сообщение; на уровне «24 часа и меньше» копия уходит второму ответственному, если указан его `chat_id`.

## Быстрый старт
1. Положите таблицу в папку файлов n8n под именем `assets.csv` (для Docker это `/home/node/.n8n-files`).
2. Для проверки SSL задайте переменную окружения n8n `NODE_FUNCTION_ALLOW_BUILTIN=tls` и перезапустите n8n.
3. Импортируйте `billing_monitor_n8n.json`, создайте учётные данные Telegram (токен от BotFather хранится только в n8n).
4. В узле `Остаток дней и уровень` впишите `CHAT_MAIN` (и при желании `CHAT_ESCALATION`).
5. Запустите вручную, затем включите сценарий.

Подробности и частые ошибки: `Инструкция.txt`.

## Честные ограничения
- Сценарий проверен автором только на структуру JSON и связи узлов; **на живом экземпляре n8n не запускался**. Проверьте после импорта.
- Для доменов используется RDAP (современная замена WHOIS). Классический WHOIS по порту 43 штатным узлом n8n недоступен.
- Через `rdap.org` зоны `.ru` и `.рф` не отдаются (запрос для `yandex.ru` 2026-11-08 вернул 404): для них используйте `kind=manual` и дату из кабинета регистратора.
- Публичные серверы WHOIS и RDAP ограничивают частоту запросов: не ставьте интервал в минуты и не загружайте сотни доменов за один запуск.
- Проверка SSL работает только для хостов, до которых доходит сервер n8n.
- Сценарий только предупреждает, он ничего не оплачивает и не продлевает. Автоплатёж после перевыпуска карты проверяйте сами.
- Таблица `assets.csv` единственный источник данных: делайте её копию на другом носителе (правило 3-2-1).
- Названия, суммы, домены и даты в шаблоне вымышленные примеры; проверяйте актуальные условия сервисов.
